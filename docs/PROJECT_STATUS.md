# Implementation status

The desktop app now calculates a monthly or semi-monthly payroll estimate for the supported rule scope in `docs/GOVERNMENT_SOURCE_REVIEW_2026.md`. Java validates earnings and the effective government-table CSVs; the COBOL coordinator loads the passed table values and calls the gross-pay, SSS, PhilHealth, Pag-IBIG, BIR, deduction, net-pay, and employer-cost modules. The result includes employee/employer shares, taxable compensation, withholding tax, net pay, and employer cost. Unsupported or incomplete rule data fails closed.

The calculation is deliberately narrow: ordinary private-sector employee, supported pay frequency, only basic salary/overtime/taxable allowance inputs, all earnings taxable, and equal splitting of monthly contribution amounts across semi-monthly checks. It does not model employee-specific exemptions, MWE status, absences, partial months, non-taxable/de-minimis benefits, 13th-month pay, loans, annualized year-end adjustments, or remittance/reporting requirements. Successful calculations are retained as timestamped employee history snapshots, but remain estimates that cannot be approved/finalized or issued as payslips. Review `docs/GOVERNMENT_SOURCE_REVIEW_2026.md` before relying on any result.

Other implemented features include JavaFX navigation, employee create/read/update/delete, settings, SQLite persistence with optional MySQL JDBC connection, SQLite backup/restore, employee audit entries, timestamped payroll history, and draft payroll periods. Employees with payroll history must be archived instead of deleted.

Still pending: authentication and roles; full employee statutory-profile fields; payroll-entry review/approval/finalization and adjustment workflow; payslips and statutory reports; effective-date selection across multiple bundles; source PDF archiving/checksums; extensive boundary and rounding tests; and Windows installer packaging. This project is not ready for unattended production payroll.
